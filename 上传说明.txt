GitHub Pages 发布步骤（访客和现场操作者无需登录）

一、先让网站公开运行
1. 解压 ZIP。打开解压后的文件夹，能看到 index.html、admin.html、assets 文件夹等。
2. 登录你的 GitHub 账号，新建仓库，例如 collectibles-giveaway，选择 Public。
3. 在仓库里选 Add file → Upload files，把解压后的内容全部上传并 Commit。
   重点：index.html 必须直接位于仓库根目录。不要只上传 ZIP，也不要多套一层文件夹。
4. 打开 Settings → Pages。
   Source 选 Deploy from a branch；Branch 选 main；Folder 选 / (root)；点 Save。
5. 等 GitHub 显示发布地址，通常形式为：
   https://你的用户名.github.io/collectibles-giveaway/
6. 展示端打开上面地址；管理端打开：
   https://你的用户名.github.io/collectibles-giveaway/admin.html
   发布后的网页本身不需要登录。搭建时你需要登录自己的 GitHub 账号。

默认已经能做什么
- 内置已核对的 149 人名单，默认允许重复中奖，管理端可修改。
- 最多 2,000 个不重复名字；首次使用是新的中奖记录，不包含旧站测试记录。
- 名单修改、中奖记录保存在当前浏览器；同一浏览器两个标签页可以同步。
- 拉杆 / 右下角按钮触发抽奖，键盘空格与回车不触发；小喇叭控制声音。
- 展示端和管理端先在线打开一次，等待资源缓存，再断网仍可刷新、抽奖。

重要：两个不同设备实时同步，需要完成下面第二部分。
单靠 GitHub Pages 不会把两台电脑的浏览器存储连起来。

二、两台设备实时同步（无登录的共享后端）
需要网站搭建者有 Cloudflare 账号。现场打开网站的人不需要 Cloudflare 账号。

1. 在 Cloudflare Dashboard 找到 Workers & Pages，创建一个 Worker。
   可先部署 Hello World，再进入代码编辑，把 backend/worker.js 的全部代码替换进去并部署。
2. 在 Cloudflare 的 D1 页面创建数据库，例如 collectibles-draw。
3. 打开这个数据库的 Console，把 backend/schema.sql 的内容粘贴进去并执行。
4. 回到 Worker 的 Bindings，添加 D1 database 绑定：
   Variable name 必须是 DB；选择刚才的数据库；保存并重新部署 Worker。
5. 复制 Worker 的 HTTPS 地址，例如：
   https://collectibles-shared-draw.你的子域.workers.dev
   浏览器打开该地址应看到 ok: true 的 JSON。
6. 两台设备都打开 GitHub Pages 的 admin.html。
   在底部展开 Shared sync settings，输入同一个 Worker 地址，点 Connect / reconnect。
   看到 Shared sync connected 就表示进入共享模式。第一次连接空数据库时，会初始化 149 人名单。
7. 展示端保持全屏，另一台设备修改名单。
   抽奖开始后，本轮名单锁定；新的修改从下一轮生效。

可选：不想每台设备手动输入时，直接在 GitHub 修改 config.js：
window.GIVEAWAY_CONFIG = { apiUrl: "https://你的Worker地址" };
保存后，清除旧的手动配置或在管理端重新连接。

三、断网 / 后端异常时怎么做
- 后端断开后，展示端会切换为 Offline fallback，仍可用保存的名单继续抽奖。
- 离线结果会留在本机，刷新仍保留。恢复网络不会自动覆盖这些本地结果。
- 恢复联网前，先用 Export results 导出本机中奖记录，再在 Shared sync settings 重新连接。
- 如果抽奖请求发出后丢失响应，系统会提示 Shared result uncertain 并暂停：
  先检查另一台展示是否已经开奖，再决定重连，或在管理端明确选择 Use local mode。
  这样可以避免因为超时静默重抽出另一个结果。
- 活动现场只让展示端负责抽奖。断网时两台设备同时抽奖，无法保证全局不重复。
- 不要清理浏览器数据，也不要依赖关闭后会清空的无痕窗口保存中奖记录。
- 第一次从未打开过的网站，在完全断网时无法加载；请提前打开两页完成缓存。

四、公开意味着什么
这个版本按你的要求不设权限。任何知道网站或后端地址的人都可能编辑或抽奖。
seed.js 中的 149 人名单会随公开仓库一起公开。
请使用这个干净 ZIP 建立新仓库，不要把旧项目的 Git 历史一起 push；旧历史包含早期演示稿素材。

五、测试与更新
- 已测试内置 149 人、本机抽奖后刷新恢复、断网后刷新加载、共享接口并发锁定、
  离线结果不被迟到的云端响应覆盖、不确定的共享抽奖不静默重抽。
- 不能保证所有网络、浏览器和并发场景绝无故障，活动前请用实际两台设备彩排。
- 将来更新文件时，修改 sw.js 顶部 CACHE 的版本名，然后在线刷新，让离线缓存更新。
